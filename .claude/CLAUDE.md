# Oracle Silver DBA 学習プロジェクト — Claude Code 設定

## プロジェクト概要

Oracle Database Silver（Bronze + Silver）の資格取得と DBA としての実践スキル習得を目的とした
学習環境です。GitHub Codespaces 上で Oracle Linux 8 + Oracle Database 21c XE を使い、
全23章・7モジュールを実機演習で学びます。

**カリキュラム詳細**: `{プロジェクトフォルダ}/docs/plans/main-plan.md` を参照してください。

## 利用可能なエージェント（カスタムスラッシュコマンド）

このプロジェクトには3つの専門エージェントが定義されています。
用途に応じて呼び分けてください。

| コマンド | エージェント名 | 役割 |
|---|---|---|
| `/plan` | 計画者 | カリキュラムの章構成・学習目標・実習内容を計画・更新する |
| `/draft-chapter` | 新人教育担当者 | 各章の README.md を作成し、品質を評価する |
| `/verify-db` | Oracle DB マスター | SQL・DBA コマンドをコンテナ内で実行し、教材の正確性を検証する |

---

## ワークフロー

作業は必ず以下のステップで進めること。

1. **探索 (Explore):** 既存コードや README を `grep` / `read` で調査し、現状を把握する。
2. **計画 (Plan):** 修正方針を `{プロジェクトフォルダ}/docs/plans/` 配下に Markdown で作成し、ユーザーの承認を得る。`@plan` を活用して影響範囲・実装手順・検証コマンドを整理する。
3. **実装 (Implement):** 承認された計画に基づき、`@verify-db`（コード）または `@draft-chapter`（文書）が作業する。
   - **自律修正:** 教育的観点からの改善（優先度高・中）は、エージェントが自律的に連続して修正・検証を繰り返すことを許可する。
4. **検証 (Verify):** 学習対象のツールに合わせて、適切なコマンドでビルドと実行を確認する。

## README 作成ルール

全エージェントが README.md を作成・評価する際は以下のルールに従ってください。

### セクション構成（必須）

1. **章タイトル・概要** — 何を学ぶか、なぜ重要かを 2〜3 文で説明
2. **学習目標** — 箇条書き（動詞で始める: 「〜できる」「〜を理解する」）
3. **説明本文** — 概念説明 + 図・例（初学者が「なぜ必要か」を理解できる内容）
4. **ハンズオン手順** — 番号付きステップ、実際のコマンドをコードブロックで提示
5. **確認してみよう** — 3〜6問（下記ルール参照）
6. **ナビゲーションバー** — 最終行（下記ルール参照）

### 確認してみようセクションのルール

```markdown
## 確認してみよう

1. （問い）
2. （問い）
3. （問い）
```

- 問い数は **3問〜6問** とする
- 「〜とは何ですか？」「なぜ〜が必要なのですか？」など理解度を問う形式にする
- 単純な「Yes/No」で答えられる問いは避ける
- 回答は記載しない（学習者自身が考える余白を残す）
- 問いの順番は「簡単 → やや難しい」の順

### ナビゲーションバーのルール

```markdown
| [← 第NN章: タイトル](../前章フォルダ名/README.md) | [全章目次](../README.md) | [第NN章: タイトル →](../次章フォルダ名/README.md) |
|:---|:---:|---:|
```

- ルート `README.md` へのパスは **`../README.md`**（章フォルダから1階層上）
- 前章がない場合: 左セルを空欄にする
- 次章がない場合: 右セルをリンクなしのテキスト `最終章` にする
- ナビゲーションバーの直前に `---` 区切り線を入れる

## Markdown 編集ルール

- 編集後は markdownlint-cli2 と textlint を実行し、エラーがゼロになるまで修正する
- markdownlint-cli2 と textlint の指摘事項の修正はユーザーの承認を得ず、自動的に修正する
- コマンドが見つからない場合は処理を中断してユーザーに確認する
- mermaid記法をサポートしているため、主にOracleDBとのやり取りが発生する章ではシーケンス図を積極的に使用する
